# v1.13.0 有限验收基准

## 用户范围决定

2026-10-16，用户在 issue 推进中提出"如果实在没有什么推进了可以发个中版本"；看到首轮验收结果（S1 中
`zone move` 重画框间歇失败）后选择"先修再发"：修复后在新候选上重跑全部用例，再发 v1.13.0。本次沿用
v1.12.0 的有限范围：按 `cli-fixes` 发布，`full-design-e2e` 延期至 `follow-up`。完整设计 E2E 不补签。
该决定只绑定本版本，不改变其他版本的默认验收要求。

## 候选与输入

产品源码候选为 dev 提交 `e5ed0fb`（v1.12.0 之后 24 个提交）。连接器运行时自 v1.12.0 起有改动（库资产
build 核对与焊盘元组校验、`pcb.component.modify` 层名换数字 id、保留器件清页的引脚闭包、无网表实例的引脚网
解析、规则回读标准形式、typed `schematic.text.move`、`pcb.route.delete` 内嵌对象判据），按版本规则递增
minor；CLI/daemon、连接器、npm/lock 与 Skill 正式版本统一为 1.13.0。

现场 CLI/daemon 由该候选构建（`v1.12.0-24-ge5ed0fb-dirty`，dirty 仅为 `make eext` 产生的未提交连接器版本号）；
连接器为 `4ba12a2` 源码构建的开发包，经 IndexedDB 热重载装入（现场 1.12.19，`dist/index.js` SHA256
`c73809aa511308c1bda73b64eff08c226ba23568f69933f33b13378c09b9ed43`），`extension/src` 自 `4ba12a2` 至候选无改动。
正式包只同步版本号、Changelog 与发布材料。

现场使用获准的 ceshi 专用测试工程。开始状态：原理图 P1 只有图框；PCB1 为 #43 先前导入的 ESP32-S3R8 块
16 个器件（无板框、无走线，另有 2 个 GND 过孔），语义哈希基准 `1a625faf0ee47601…`。原 ESP32-S3 最小点灯板已在 #43 开始前
备份到本地忽略目录。工程身份、原始日志与本地路径不公开。

## 环境与阈值

macOS arm64，Chrome 中的 Web EDA 4.1.78（V4 主线；v1.12.0 验收时为 4.1.71）。全部现场用例在 EDA 标签页
后台（`pageVisibility` 为 hidden）下执行。有限用例 M1/F1/F2/E1/L1/N1/R1 及 S1/K1/P1 的含义以本目录
test-cases.md 为准；它们不是完整设计用例的补签。
阈值：拒绝路径零写入、现场写入均回读核验、重载后状态一致、清理后 PCB 语义哈希与基准一致。
本板无布线，原生 DRC 不以 passed 为阈值，而要求违例全部可由板状态解释（见 E1）。

完整 B00–B10、完整设计与制造验收不在本次通过范围。
